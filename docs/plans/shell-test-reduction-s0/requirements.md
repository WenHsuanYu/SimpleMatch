# S0 verification requirement ledger

Source baseline: `7b9d2fd035632aa6797ad1d771a90c96b5062a87`.
Issue: [#197](https://github.com/WenHsuanYu/SimpleMatch/issues/197). Approved program: [#196](https://github.com/WenHsuanYu/SimpleMatch/issues/196).
This ledger preserves requirements, not historical helper shapes or phase counts.
It records planned replacement owners. S0 does not implement those replacements.

## Reading the ledger

The [file ledger](script-ledger.md) assigns every baseline Shell file to these requirements and a delivery batch.
The [JSON ledger](script-ledger.json) contains current implementation hashes, textual callers, embedded tools, owners, and deletion conditions.
Its references include tests, documentation, comments, and workflow mentions. They are not all executable callers.
Resolve ambiguous basenames and variable-generated calls before deleting a file.

The common deletion gate applies to every retained requirement:

1. The replacement exercises the required public behavior, including meaningful negative cases.
2. Direct callers, sourced imports, documented operator entries, and evidence readers use the replacement.
3. Obsolete framework tests disappear with their framework. Necessary regressions remain at the replacement seam.
4. The relevant focused and complete checks pass. Required unresolved failures remain blockers.

## Current complete coverage boundary

The default phase selector emits 62 ordered phase IDs at this baseline.
The [bounded evidence](evidence.json) records those IDs without executing adapters.
Its final root is retained-run provenance, not an automatic execution of all dependent business scenarios.
The [dated complete record](../../verification/current-local-certification.md) separately lists six business/restoration scenarios and throughput measurements.
The new complete task must include those necessary behaviors and current Query security acceptance through an explicit requirement mapping.
It must not claim that the old 62-phase invocation already covers them automatically.

Normal Gradle tests, native CTest, security integration and static analysis also remain necessary where the development workflow requires them.
The ledger does not convert external production templates, production capacity, or historical certification claims into new local acceptance.
See the [execution plan](execution-plan.md) for concrete scenario batches and blockers.
