# Gateway admission operations

The single Phase 1 QuickFIX Gateway is the only authority that decides whether new orders and
cancellations may enter the durable admission path. It is not a replacement for Risk, Matching, or
Kubernetes ownership: it combines their reported facts into one admission decision.

## Gate states

| State | New orders | Cancellations | Meaning |
| --- | --- | --- | --- |
| `PRE_OPEN` | rejected | rejected | Process start or incomplete operational evidence. |
| `OPEN` | accepted | accepted | Three fresh complete ready observations passed and an operator opened the session. |
| `NEW_ORDERS_PAUSED` | rejected | accepted | Existing orders may still be cancelled while a bounded recovery catches up. |
| `MARKET_INTERRUPTED` | rejected | rejected | Identity, topology, or deterministic-integrity evidence is contradictory. |
| `CLOSED` | rejected | rejected | Terminal state for this Gateway process's trading day. |

The FIX ingress gate applies these permissions before WAL and Risk submission. A pause is global to
new orders, not a reassignment of the affected Matching partition; healthy partitions drain their
already admitted commands while a recovering partition retains its backlog and cancellations in
`matching.commands`.

## Application commands

`GatewayOperationalCommandHandler` accepts exactly five transport-neutral operations:

```text
status
open
pause-new-orders
interrupt-market
close-day
```

Every changing command carries an operator identity and a non-empty reason. Its accepted or rejected
outcome, gate state, readiness, and time are retained in `quickfix_gateway.gateway_operation_audit`.
`open` requires three separately reported `OPEN_ELIGIBLE` observations; it cannot reopen after
`CLOSED`. Recovery becoming healthy does not issue an implicit open.

## Authenticated HTTP operation

The existing internal HTTP adapter calls `GatewayOperationalCommandHandler`; an operator does not
need a new shell script to open trading. The adapter is disabled by default. Deployment must set
`SIMPLEMATCH_QUICKFIX_GATEWAY_OPERATIONS_HTTP_ENABLED=true` and supply
`SIMPLEMATCH_QUICKFIX_GATEWAY_OPERATIONS_OPERATOR_TOKEN` through a Secret reference. A blank token
with HTTP enabled fails startup. Workload identity, per-user RBAC, network-policy enforcement, and
production security certification are not provided by this shared-token adapter.

The operator token is externally provisioned, not generated by Gateway or derived from Risk's
trading identity. With shell tracing disabled, a deployment operator can generate 32 random bytes
directly into a private temporary file, without displaying the value:

```bash
umask 077
GATEWAY_OPERATOR_TOKEN_FILE="$(mktemp /tmp/simplematch-gateway-operator-token.XXXXXX)"
openssl rand -hex 32 | tr -d '\n' > "$GATEWAY_OPERATOR_TOKEN_FILE"
GATEWAY_OPERATOR_HEADER_FILE="$(mktemp /tmp/simplematch-gateway-operator-header.XXXXXX)"
printf 'X-SimpleMatch-Operator-Token: %s\n' "$(<"$GATEWAY_OPERATOR_TOKEN_FILE")" \
  > "$GATEWAY_OPERATOR_HEADER_FILE"
```

Provision that exact value through the deployment's Secret-management workflow. The file has mode
0600 and no trailing newline; do not regenerate it without coordinating the deployed Secret and
operator credentials. Keep the exact token out of terminal output, command arguments, shell
tracing, repository files, and retained reports. Remove the temporary token file after provisioning
both the deployment Secret and the operator's protected header credential. An operator's `actor`
and `reason` are audit context; the shared token is not independent proof of the named person's
identity.

The checked-in local overlay deliberately leaves HTTP disabled: port-forwarding alone is not
enough. In a dedicated disposable lab namespace, an authorized deployment operator must first
create a run-owned Secret, add only the HTTP-enabled environment value and operator-token
`valueFrom.secretKeyRef` above to the Gateway Pod template, and wait for its StatefulSet rollout.
Capture the original Pod template before doing this. After the local exercise, restore those
temporary overrides, wait for rollout, verify the original template is restored, and only then
delete the run-owned Secret. Do not change freshness, monitoring, or automatic-close settings.
This rollout restarts admission in `PRE_OPEN`; do not apply it to an active trading deployment.
Secure overlays instead reference their configured operations Secret and require that Secret to
be provisioned through the normal deployment workflow, not a temporary local override.

The following plaintext HTTP example is for the local lab overlay only. For a secure deployment,
use HTTPS with the deployment's approved CA/trust configuration and a hostname covered by the
server certificate, including when forwarding the port; never bypass verification with
`--insecure`. First establish the local kind port-forward in a separate terminal:

```bash
kubectl --context kind-simplematch-live -n "$GATEWAY_NAMESPACE" \
  port-forward statefulset/quickfix-gateway 18080:8080
```

`GATEWAY_NAMESPACE` must identify the intended running deployment. The generated permission-0600
header file contains `X-SimpleMatch-Operator-Token: <the exact provisioned token>`;
`GATEWAY_OPERATOR_HEADER_FILE` below is its path, not the token value. Do not print that file or
commit it; delete the private header file after the operation. Query status, then send the explicit
open command only after reviewing readiness:

```bash
curl --fail-with-body --silent --show-error --connect-timeout 2 --max-time 10 \
  --header "@${GATEWAY_OPERATOR_HEADER_FILE}" \
  http://127.0.0.1:18080/operations/status

curl --fail-with-body --silent --show-error --connect-timeout 2 --max-time 10 \
  --header "@${GATEWAY_OPERATOR_HEADER_FILE}" --header 'Content-Type: application/json' \
  --data '{"actor":"local-operator","reason":"Daily pre-open checks complete"}' \
  http://127.0.0.1:18080/operations/open
```

An HTTP 200 response is not sufficient: manually inspect the returned JSON and require
`accepted: true` and `gateState: "OPEN"`. Status polling is read-only and does not create qualifying
observations. Gateway's live collector must supply three separate fresh complete `OPEN_ELIGIBLE`
observations; an operator cannot bypass missing or unsafe evidence. Normal operations must not
post fabricated documents to `/operations/observations`. Recovery to healthy readiness still does
not open automatically, and `CLOSED` is terminal for the current Gateway process. Default session
close is 13:30 Asia/Taipei; the local lab overlay alone uses 23:59 without disabling automatic close.

## Automatic safety actions

The scheduled monitor evaluates the most recent complete observation at least every second. It:

- pauses new orders if required status is more than five seconds old, a component is unavailable,
  a partition is unrecovered, or a required consumer has lag;
- records a warning at 30 seconds for the oldest pending critical event and requires a pause at 120
  seconds;
- interrupts the market for identity/schema/artifact/algorithm/image mismatch, invalid fixed Kafka
  topology, quarantine, or the same event ID with different raw payload bytes; and
- closes the session at 13:30 Asia/Taipei by default.

No Matching Event is required for readiness: an empty partition reports its committed offset equal to
its end offset and has no oldest pending-event age.

## Status input boundary

The evaluator accepts only `RiskStatus`, `MatchingFleetStatus`, `CriticalConsumerStatus`, and
`KafkaStatus`. Infrastructure adapters must normalize Kubernetes Lease/readiness data, Kafka end
offsets, and service-owned status endpoints into these values. Kubernetes and Kafka classes do not
enter the domain controller.

The production collector now reads Risk's verified trading identity, all fifteen Matching runtime
documents, Kafka topology/end offsets/acknowledged group commits, and critical-consumer pending
ages and quarantine state. The 15 owners are the configured one-owner-per-partition Matching
fleet, not another group of 15 processes. Full trading identity comparison is limited to Risk
and these Matching owners; Kafka and consumers neither attest full trading identity nor receive
a copy of Risk's identity.

Matching command progress is Kafka's acknowledged commit for each
`matching-partition-consumer-<partition>`, not native `next_commit_offset`, which is a pending
candidate and can legitimately be null. Missing progress on a non-empty log and malformed
negative offsets fail closed. An empty log without a commit can normalize to zero progress.

Each I/O is bounded to one second and the complete collection to three seconds. Failed or
incomplete collection does not republish the last successful observation as fresh. The separate
monitor applies the existing five-second expiry and safety action. Infrastructure types remain
outside the admission evaluator; there is still one admission policy and one state machine.

The source-aligned local deployed smoke verifies `PRE_OPEN`, healthy production observations,
and authenticated explicit open without posting synthetic observations. Its evidence and limits
are recorded in the [completion specification](../../../docs/gateway-admission-completion.md#deployed-admission-smoke)
and the
[Phase 1 remaining-work inventory](../../../docs/routing-policy-remaining-work.md#go-1-operate-one-gateway-admission-authority).
